# FindTax 수익 성장 전략

작성일: 2026-09-24  
범위: 검색 유입, 네이버 원문과의 콘텐츠 연계, 계산기 확장, AdSense 및 후속 수익원. 이 문서는 계획이며 애드센스 설정·사이트 코드·운영 배포는 변경하지 않았다.

## 1. 지금 확인된 기준선

- Search Console의 최근 3개월 화면: 노출 13회, 클릭 0회, 평균 게재순위 18.1. 표시된 검색어는 `findtax`, `찾아줘 세무사`, `기타소득 계산기` 각 1회 노출이었다. 이는 성장률이나 키워드 수요를 추정하기엔 매우 작은 표본이다.
- 제출 사이트맵은 성공, 발견된 페이지 65개로 표시된다. 사이트맵의 마지막 읽기 날짜는 2026-09-11이므로 재방문 수집은 계속 관찰해야 한다.
- 애드센스 정책 센터는 현재 정책 위반 문제와 광고 게재 제한이 없다고 표시한다.
- 페이지 제외 12개는 `/about`, `/admin`, `/auth`, `/case`, `/consult`, `/editorial-policy`, `/my-taxes`, `/partner`, `/privacy`, `/register`, `/support`, `/terms`다. 섹션 제외 규칙이 하위 경로에도 적용되는 화면이므로 `/consult/thank-you`와 상태 페이지는 `/consult` 아래에 포함된다.
- 자동 광고 사용 중. 오버레이 형식은 앵커 광고와 사이드 레일 광고가 켜져 있고 모바일 전면 광고는 꺼져 있다. 인페이지 형식은 2/2 사용으로 표시된다.
- 자동 광고 실험은 2026-09-23~2026-12-22, 대안 50%, 자동 적용 사용 중이다. 확인 시점 실험 노출은 0회라 승자 데이터가 없다. 아직 시작 하루 정도라 중단/재설정하지 않는다.
- 데스크톱 글 화면에서 하단 고정 앵커가 뷰포트 아래쪽 본문 몇 줄을 가리는 장면을 확인했다. 애드센스 모바일 미리보기에서도 앵커가 하단 고정으로 표시됐다. CLS는 실측하지 않았다. 홈 첫 화면에는 광고가 보이지 않았다.
- 기존 자료에 기록된 계산기는 SEO 카탈로그 12개와 별도 노후월급 계산기 등이 있다. 연금·IRP 절세 시뮬레이터, 4대보험 계산기, 세금 계산기들이 이미 있어 새 도구 추가 전에 중복·정확성 검토가 필요하다. 기존 블로그 집계는 57개(9월 13일 스냅샷)로, 현재 개수는 다시 세지 않았다.
- 지금의 우선 과제는 광고 밀도를 더 높이는 것이 아니라 검색 노출과 측정 가능한 방문을 만드는 것이다. 수익은 실제 AdSense 페이지 RPM·세션·국가·기기 자료를 확보한 뒤 비교한다.

## 2. 목표와 성장 모델

**핵심 목표:** FindTax의 세무·사업자 실무 전문성을 유지하면서 검색 방문자가 필요한 답과 계산 결과를 얻고, 자연스러운 다음 페이지 이동으로 페이지 RPM을 높인다.

단순화한 성장식은 `검색 노출 × 클릭률 × 유효 방문당 페이지 수 × 페이지 RPM`이다. 단기에는 광고 슬롯을 늘리는 것보다 노출·클릭·체류와 페이지 품질의 병목을 푸는 편이 우선이다. 블로그에서 계산기로 이어지는 클릭과 계산 완료를 개인정보 없이 측정하고, AdSense 수익은 AdSense 보고서의 수익/페이지뷰 지표로 따로 확인한다. 검색 클릭, GA4 세션, 광고 수익을 같은 숫자로 취급하지 않는다.

## 3. 네이버 글 → FindTax Google 버전 운영

네이버 원문을 문장만 바꿔 재게시하지 않는다. 원문 작성자의 관찰과 실무 경험은 유지하되 FindTax 버전은 Google 독자의 질문에 맞춘 **별도 완성 콘텐츠**로 만든다.

### 편집 흐름

1. importer에서 원문 URL, 글의 핵심 질문, 사실·경험·의견의 구분, 재사용 가능한 표/사례, 최신 확인일을 입력한다.
2. 세금·보험·투자 규정은 공식 기관 자료를 다시 확인하고, 적용 연도와 계산 가정을 본문에 표시한다. 원문에 없는 사실과 결과를 덧붙이지 않는다.
3. FindTax 글에는 고유한 설명, 사례 또는 비교표, 한계와 관련 계산기 연결 중 최소 한 가지 실질 가치를 추가한다. 원문 요약만으로 페이지를 만들지 않는다.
4. 적절한 위치에 `네이버 원문/작성 과정` 링크를 한 번 자연스럽게 두고, 네이버 글에도 해당 FindTax 계산기나 보충 설명이 실제로 도움이 될 때만 역링크를 단다. 모든 글에 기계적으로 상호 링크하지 않는다.
5. 초안은 사실·출처·계산기 링크·광고 표시·저작권 검수 후 발행하고, 내용이 실질적으로 바뀐 경우에만 수정일을 갱신한다.

원문 링크는 독자가 출처와 작성 과정을 확인하게 돕고 검색로봇 발견을 보조할 수 있지만, 네이버 글의 Google 색인이나 순위를 보장하는 수단은 아니다. Google은 원본을 단순 요약·재작성하거나 대량 자동 변환한 페이지가 사용자에게 부가 가치를 주지 않는 경우를 문제 삼는다. 네이버 링크도 순위 조작 목적의 과도한 교환이 되지 않도록 편집상 필요할 때만 둔다. ([Google 사람 우선 콘텐츠 안내](https://developers.google.com/search/docs/fundamentals/creating-helpful-content), [Google 스팸 정책](https://developers.google.com/search/docs/essentials/spam-policies))

### 주제 경계

- FindTax의 중심: 개인사업자·N잡·세금·급여·연금·사업 운영 계산.
- 보험: 보험 판매 일반 사이트처럼 확장하지 않고 세금·가계 현금흐름과 직접 연결된 설명부터 제한적으로 추가한다. 자격 보유 사실은 정확히 표기하되 세무사 자격이나 개별 보험 적합성 판정으로 오해되지 않게 한다.
- 투자: 상품 추천·수익 보장 대신 복리의 수학, 세후 금액, 가정별 장기 차이를 설명한다. 예상값과 실제 수익을 분리한다.

## 4. 계산기 확장 우선순위

정확한 검색량 순위는 현재 자료로 확인되지 않았다. Google Trends는 절대 검색 건수가 아니라 지역·기간 내 상대 관심도(0~100)를 보여주며, Search Console은 지금 표본이 너무 작다. 따라서 아래는 **수요 검증 대상과 제품 적합성에 따른 가설**이지 검색량 확정 순위가 아니다. 다음 단계에서 Search Console 쿼리, Google Ads 키워드 플래너의 한국 월간 검색 범위, 네이버 데이터랩 추세, 실제 사용률을 같이 본다. ([Google Trends 데이터 설명](https://support.google.com/trends/answer/4365533?hl=ko))

| 우선순위 | 후보 | 제안 |
| --- | --- | --- |
| 1 | 예금·적금 세후 이자 계산기 | 세전/세후, 기간, 이자 방식, 납입 주기와 세금 가정을 입력. 기존 세금 계산기와 연결되어 FindTax 적합성이 높다. 법령·상품별 예외 안내가 필요하다. |
| 2 | 복리·적립식 투자 시뮬레이터 | 초기금+정기 납입+기간+가정 수익률을 비교하고 원금/수익/물가 반영 금액을 나눠 표시. 특정 상품 추천 없이 가정의 민감도를 보여준다. 금융 키워드는 경쟁이 세므로 콘텐츠 차별화와 수요 테스트 후 개발한다. |
| 3 | 연금저축·IRP 납입 및 수령 시나리오 보강 | 이미 절세 시뮬레이터와 노후월급 계산기가 있으므로 먼저 내부 링크·기능·검색어 수요를 점검한다. 기존 기능을 새 이름으로 중복 개발하지 않는다. |
| 4 | 보험 관련 세금 안내/계산 | 먼저 보험료 세액공제 등 세금과 직접 연계되는 설명 콘텐츠로 시험한다. 개인 보장분석, 해지/가입 권유 계산기는 약관별 차이와 규제·정확성 검토를 마치기 전 보류한다. |

**계산기 출시 기준:** 실제 검색 질문과 연결된 고유 입력/출력, 공식 근거와 갱신 책임자, 대표·경계 사례 검증, 계산 한계, 모바일 결과 가독성, 오류 보고 경로, 관련 글/계산기 내부 링크를 갖춰야 한다. 계산기 숫자만 바꾼 수백 개 지역·키워드 페이지는 만들지 않는다.

## 5. 트래픽 성장 전술

### 먼저 할 일

- Search Console에서 매주가 아니라 월 1회 쿼리/페이지/기기별 노출·CTR·순위를 저장하고, 노출은 생겼지만 클릭이 없는 페이지부터 제목·설명·첫 답변을 개선한다.
- 한 주제군 안에서 `질문을 해결하는 글 → 관련 계산기 → 계산 가정/공식 출처`를 연결한다. 중요한 페이지는 관련 글 2~4개에서 발견 가능하도록 링크한다.
- 색인 상태는 sitemap 성공만으로 판단하지 않는다. 대표 URL의 색인 여부, canonical, 크롤링·렌더링, 실제 검색 실적을 분리 확인한다.
- 처음 8~12주 동안 발행량 목표를 강제하지 말고, 주 1~2편 정도의 검수 가능한 주제 실험을 기준으로 삼는다. 반응이 확인된 주제를 깊게 보완한다.
- 네이버에서 먼저 반응한 질문은 FindTax에서 세무 규정의 적용 연도·계산기·공식 근거를 더한 후속 글로 발전시킨다. 네이버 방문을 인위적으로 돌리거나 검색 클릭을 구매하지 않는다.
- 이메일/구독은 세금 일정 알림이나 계산 기록처럼 재방문 가치를 제공할 준비가 된 뒤 선택 동의, 보관기간, 수신 해지를 갖춰 도입한다.

### 유료 유입은 후순위

현재는 클릭·수익 데이터가 없어 광고비를 집행해도 회수 판단이 어렵다. 먼저 자연 유입 페이지 RPM, 계산기 이용률, 재방문을 확보한다. 이후 소액 상한과 중단 기준을 미리 정해 검색광고를 시험하고, 수익보다 비용이 큰 키워드는 즉시 끈다. 광고주·플랫폼 정책을 준수하고 AdSense 수익을 높이려는 클릭 유도/저품질 트래픽을 섞지 않는다.

### 하지 않을 단기 꼼수

가짜 클릭·노출, 클릭 보상·교환, 자동 방문, 키워드 도배, 숨긴 링크, 내용이 거의 같은 대량 AI 페이지, 지역명만 바꾼 문, 인위적 링크 구매·과도한 상호 링크, 광고를 CTA처럼 위장하는 방식은 제외한다. AdSense의 무효 트래픽 정책과 Google 검색 스팸 정책에 걸릴 수 있고 장기 수익 기반을 훼손한다. ([AdSense 프로그램 정책](https://support.google.com/adsense/answer/48182?hl=ko), [Google 스팸 정책](https://developers.google.com/search/docs/essentials/spam-policies))

## 6. 수익원 포트폴리오

1. **현재: AdSense 자동 광고.** 승인된 상태를 유지하고 콘텐츠·정책·사용자 경험을 우선한다. 유입 표본이 매우 적으므로 광고 수를 임의로 늘리거나 수동 슬롯을 급히 박지 않는다.
2. **측정 후: AdSense 실험.** 광고 로드/형식 또는 자동 광고 설정을 한 번에 한 변수씩 비교한다. 수익 변화와 모바일 가독성·이탈·CLS를 같이 평가하고, 충분한 표본이 없으면 승자를 선언하지 않는다. AdSense는 Auto ads 설정 실험을 지원한다. ([Auto ads 실험 안내](https://support.google.com/adsense/answer/9726342?hl=en))
3. **후속: 명확히 표시한 제휴·스폰서 콘텐츠.** FindTax 편집 판단을 유지하고 광고/제휴 사실을 눈에 띄게 표시한다. 유료 링크에는 적절한 `rel="sponsored"` 또는 `nofollow`를 적용한다. 제휴 금융·보험 상품은 법률·광고 규정과 실제 자격·계약 범위를 확인한 뒤 시작한다.
4. **후속: 전문 서비스/상담 전환.** 상담 CTA는 서비스 제공·응대·개인정보 처리 준비가 실제로 끝난 뒤 활성화한다. 현재는 사용자가 상담 CTA를 활성화하지 않았으므로 수익 극대화의 당면 목표로 두지 않는다.
5. **장기: 유료 도구/리포트.** 무료 계산 결과에 필요한 설명을 숨겨 결제를 강요하지 않고, 사용자에게 추가 가치를 주는 저장·비교·보고 기능이 검증된 경우에만 시험한다.

## 7. 광고·사용자 경험 가드레일

- 현재 단계에서는 자동 광고를 유지하는 것이 합리적이다. 먼저 제외 경로와 실제 PC/모바일 노출을 점검하고, 콘텐츠 첫 답변·계산기 입력·결과·버튼을 덮는지 확인한다.
- 하단 고정형 광고나 닫기 어려운 팝업을 수익 목적으로 추가하지 않는다. 광고는 탐색·계산 인터랙션과 명확히 구분하고 오클릭을 유발하지 않아야 한다. 정책 센터가 깨끗하다는 사실은 개별 배치 UX까지 자동 보증하지 않는다.
- 레이아웃 공간을 예약하고 배너/광고의 크기 변화를 측정한다. PC와 모바일을 나누어 CLS와 핵심 콘텐츠 가림을 확인한다. 단 한 번의 캡처가 아닌 여러 방문 세션에서 광고 채움 변동도 고려한다.
- 민감·기능성 화면(상담/로그인/관리자/신청 완료/내 세금/개인정보·약관 및 계산 과정에 집중해야 하는 화면)은 광고 제외 대상으로 검토한다. 실제 애드센스 제외 목록은 변경 전 정확한 경로를 대조하고 승인 없이 수정하지 않는다.

## 8. 실행 우선순위

길게 기다리는 일정 대신 아래 순서로 즉시 처리한다.

1. **완료(로컬 변경):** 홈/상단 메뉴/푸터/일반 글 끝의 상담 CTA를 계산기·가이드 이동으로 전환해 현재 수익 목표와 맞춘다. 다음 배포 전에 홈페이지와 블로그 랜딩, 광고 제외 화면을 한 번에 확인한다.
2. **이번 배포 직후:** Search Console의 첫 노출 쿼리 3개와 GA4 landing page 누락 수정 후 유입, AdSense 페이지 RPM을 같은 기간으로 기록한다. 광고 실험은 이미 돌고 있으므로 별도 실험을 추가하지 않는다.
3. **즉시 콘텐츠 큐:** 네이버에서 독자 반응이 나온 세무 글부터 Google 고유 버전 3편을 연속 제작한다. 각 글은 공식 근거·고유 사례/표·관련 계산기·원문 출처를 포함하고, 글을 대량 변환해 채우지 않는다.
4. **즉시 제품 큐:** 예금·적금 세후 이자 계산기 요구사항과 공식 세율/가정표를 먼저 확정하고, 이어 복리 적립 시뮬레이터를 구현한다. 연금/보험은 기존 도구와 중복 및 규정 정확성을 확인한 뒤 확장한다.
5. **광고 조치:** 앵커가 글 하단 내용을 가리는 현상과 CLS를 여러 뷰포트에서 확인한다. 실험이 데이터를 모은 뒤 수익과 UX를 함께 비교해 앵커/로드 중 하나만 조정한다. 0노출 하루 상태에서 임의 변경하지 않는다.

## 9. 지금 승인 또는 실행이 필요한 것

전략 문서와 로컬 UI 변경은 별도다. 광고 설정·제외 경로·애드센스 코드는 변경하지 않았다. 새 UI 변경은 타입 검사를 통과했으며 운영 반영 여부는 현재 배포 상태와 작업 범위를 대조해 결정한다.
