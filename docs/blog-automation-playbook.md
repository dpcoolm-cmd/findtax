# FindTax 블로그 자동 발행 플레이북

이 문서는 매주 수·토요일에 실행되는 블로그 자동 발행 에이전트가 따르는 지침이다.
사람이 수동으로 글을 추가할 때도 같은 기준을 적용한다.

## 1. 목표

구글 검색 유입을 늘리고, 유입된 방문자를 계산기 → 상담 신청으로 연결한다.
분량 채우기가 목적이 아니다. **검색 의도에 정확히 답하는 글**만 발행한다.

## 2. 주제 선정 기준 (매 실행마다 3개)

우선순위 순으로 고른다.

1. **시즌 임박 이슈** — 지금부터 4~8주 안에 마감·신청·신고가 있는 항목
   - 예: 5월 종합소득세, 7·1월 부가세, 9월 종부세 합산배제, 10월 연말정산 미리보기, 11~12월 종부세 고지
2. **최근 제도 변경** — 세법개정안·시행령 개정·국세청 공지에서 실제로 바뀐 것
3. **고단가 리드 연결 주제** — 기장(4만P), 상속·증여·부동산(3만P) 관련 판단 주제
4. **롱테일 실무 질문** — "~해도 되나요", "~와 ~ 중 뭐가 유리한가요" 형태

### 반드시 피할 것
- 이미 발행된 slug와 같은 주제 (기존 글 목록을 먼저 확인)
- 시즌이 이미 지난 주제 (예: 8월에 "5월 종소세 신고하는 법")
- 근거를 찾지 못한 수치·요건

## 3. 정확성 규칙 (가장 중요)

세무 콘텐츠는 틀리면 신뢰와 법적 리스크를 동시에 잃는다.

- **1차 출처 우선**: 국세청(nts.go.kr), 기획재정부, 법제처. 블로그·커뮤니티는 근거로 쓰지 않는다.
- **확정되지 않은 것은 확정된 것처럼 쓰지 않는다.**
  - 세법개정안은 국회 통과 전이므로 "개정안", "확정 시 적용", "변경될 수 있음"을 반드시 명시
- **날짜·금액·요건은 검색으로 확인한 것만 적는다.** 기억이나 추론으로 쓰지 않는다.
- **단정 금지**: "무조건 환급받습니다" (X) → "환급 가능성이 있습니다, 조건에 따라 달라집니다" (O)
- 확인하지 못한 세부 요건은 **쓰지 말고 생략**한다. 애매하면 "전문가 확인이 필요합니다"로 넘긴다.
- 각 글에 `sources` 배열로 참고한 실제 URL을 남긴다.

## 4. 글 구조 규격

`lib/blog/types.ts`의 `BlogArticle` 타입을 따른다.

| 필드 | 규격 |
|---|---|
| `slug` | 한글 케밥케이스. 핵심 키워드 포함. 기존과 중복 금지 |
| `metaTitle` | 30~45자. 검색 키워드 + 클릭 유도. **브랜드 접미사 붙이지 말 것** (템플릿이 자동으로 ` | findtax.kr` 추가) |
| `metaDescription` | 70~110자. 이 글에서 얻는 것을 구체적으로 |
| `keywords` | 4~6개. 실제 검색어 형태 |
| `h1` | metaTitle과 다르게. 사람이 말하듯 |
| `intro` | 200~350자. 독자의 상황을 먼저 짚고 이 글의 역할을 밝힌다 |
| `sections` | **4~5개**. 각 `h2` + `paragraphs` 2~3개 |
| `closing` | 150~250자. 요약 + 자연스러운 CTA(계산기 또는 상담) |
| `datePublished` / `dateModified` | 실행일 (YYYY-MM-DD) |
| `sources` | 확인한 1차 출처 |

### 분량
본문(intro + 모든 h2·paragraphs + closing) 합계 **1,800자 이상**.
1,500자 미만이면 시스템이 범용 문구를 자동으로 덧붙이는데, 이는 중복 콘텐츠가 되므로 반드시 피한다.

### 문체
- 기존 글과 동일한 톤: 차분한 실무 설명체, "~합니다"
- 과장·공포 마케팅 금지 ("안 하면 큰일납니다" 같은 표현 X)
- 독자가 **다음에 무엇을 할지** 알 수 있게 쓴다

## 5. 파일 작성 절차

1. 기존 slug 전체 확인:
   ```bash
   grep -h "slug:" lib/blog/all-posts-part*.ts | sed 's/.*slug: "//;s/",//' | sort
   ```
2. 새 파트 파일 생성: `lib/blog/all-posts-part{N+1}.ts`
   - 기존 파일 중 가장 큰 번호 + 1
   - `export const BLOG_ARTICLES_PART{N+1}: BlogArticle[] = [...]`
3. `lib/blog/posts.ts`에 등록:
   - import 추가
   - `ALL_PARTS` 배열 **맨 앞**에 새 파트 추가 (최신 우선, slug 중복은 자동 제거됨)

## 6. 검증 (배포 전 필수)

```bash
npx tsc --noEmit          # 타입 에러 0이어야 함
npm run build             # 빌드 성공 + 새 slug가 정적 생성 목록에 보여야 함
```

본문 분량 확인이 필요하면 `countBlogBodyChars()` 기준 1,800자 이상인지 점검한다.

## 7. 발행

- 커밋 메시지: `blog: {주제 요약} 3편 추가 (YYYY-MM-DD)`
- `main` 브랜치에 push하면 Vercel이 자동 배포한다.
- 배포 후 `https://findtax.kr/blog/{slug}` 3개가 200으로 응답하는지 확인한다.

## 8. 실패 시

- 빌드 실패: 원인을 고치고 다시 시도. 고치지 못하면 **push하지 않는다** (라이브를 깨뜨리지 말 것)
- 신뢰할 만한 최신 이슈를 못 찾은 경우: 억지로 3개를 채우지 말고 확실한 주제만 발행한다
- 어떤 경우에도 **검증되지 않은 세무 정보를 발행하지 않는다**
